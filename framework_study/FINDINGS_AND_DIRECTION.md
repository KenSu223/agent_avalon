# 框架实验结论与论文方向

写于 2026-10-06。依据见 [RESULTS.md](RESULTS.md) 和 `results/`。

**定位**：本项目只研究 agent 记忆与持续学习，不涉及安全框架。

**PI 的判断（2026-10-06）**：第 2 点和第 3 点最可能成为论文立得住的贡献，其中**第 2 点最关键**：

> 指出现有 agent memory benchmark 把"猜对"算成了"记住"；我们设计的 benchmark 能区分模型是否真的记住了。

---

## 0. 一句话
**记忆删除内容时并不区分常识与反常识，但被删掉之后，agent 会用先验把空缺补回来。** 所以向先验回归发生在"读记忆"的时候，而不是"写记忆"的时候。直接后果是：用"合理的"事实来考记忆系统，分数会被先验大幅抬高。

## 1. 证据摘要

**实验设置**
- 11 个主流记忆系统，外加完整历史作为上限。
- 每个系统 43 个模拟用户，44 对反常识 minimal pair（C = 符合常识，I = 违背常识）。
- 写入后再经历 12 个无关会话；压缩模型统一用 Qwen3-235B。

**第 12 个会话之后的结果**

| 系统 | 真实保留率 | 只考常识题的分数 | 只考反常识题的分数 | 混合分数 | 虚高（常识题分数减保留率） |
|---|---|---|---|---|---|
| 完整历史（上限） | 1.00 | 1.00 | 0.99 | 1.00 | +0.00 |
| Mem0 1.0.11 | 0.93 | 0.99 | 0.95 | 0.97 | +0.07 |
| Mem0 2.2.1 | 0.75 | 0.99 | 0.72 | 0.86 | +0.24 |
| 中性重写 | 0.73 | 0.98 | 0.74 | 0.86 | +0.25 |
| Gemini CLI | 0.49 | 0.96 | 0.58 | 0.77 | +0.47 |
| LangMem | 0.48 | 0.99 | 0.45 | 0.72 | +0.51 |
| LlamaIndex | 0.46 | 0.98 | 0.52 | 0.75 | +0.52 |
| OpenHands | 0.15 | 0.98 | 0.17 | 0.58 | +0.82 |
| LangChain | 0.14 | 0.95 | 0.17 | 0.56 | +0.81 |
| Anthropic API | 0.09 | 0.98 | 0.15 | 0.56 | +0.89 |
| Codex | 0.07 | 0.96 | 0.12 | 0.54 | +0.89 |
| **Aider** | **0.00** | **0.97** | 0.01 | 0.49 | **+0.97** |

（来源：`results/inflation.txt`、`results/summary_all.txt`、`results/decompose.txt`。）

**机制分解**（把第 2 个会话及之后的检查点合并统计）
- 条目还在记忆里：C 和 I 的答对率都约为 1.00。
- 条目被删掉：C 仍有 0.91–0.98 答对，因为先验能猜中；I 只有 0.02–0.12，agent 直接退回常识答案。
- 反常识知识的损失中，**98–100% 来自删除**，而不是来自改写。
- 记忆文本向常识方向被改写（"翻转"）的比例 ≤1%。删除对 C、I 一视同仁，保留率之差的 CI 都包含 0；唯一的例外是 Gemini CLI，它对反常识的描述性条目反而保留得**更好**。

## 2. 被证实和没被证实的部分

**被证实：问题存在，而且很严重。**
- 用主流记忆系统搭建的 agent，对反常识知识的答对率从约 95% 掉到 1–72%（取决于系统）；对常识内容始终保持在 95% 以上。
- "记忆最需要保住的内容最容易丢"、"in-context 持续学习存在天花板"这两个论点在行为层面成立。
- 结果在 11 个系统上方向一致，CI 远离 0。

**没被证实：原先的机制。**
- "压缩本身就是 iterated learning，记忆文本会被拉向先验"这一说法不成立：删除不看内容，改写几乎为零。
- 真实机制分两步：**压缩不加区分地删除，然后读取时由先验补全。** 这更接近 Bartlett 的"重建式回忆"，而不是"传话链"。
- 保留条件：只测了强压缩模型。V3 正对照中，"从大意重建"会产生 4–5% 的单向规整。弱模型或更长的链条是否会让记忆文本本身漂移，还没有测（见 §6）。

## 3. 必须正视的风险
审稿人可能会说："删掉信息之后模型去猜默认值，这是显然的。"所以论文不能只停留在"问题存在"，而要把下面三点作为贡献。

## 4. 三个候选贡献

### 贡献 1："删除不看常识与否"本身是一个有信息量的负结果
- 理论（iterated learning、先验驱动的选择）预测删除应当偏向反常识内容。我们第一次在真实系统上把先验契合度作为受控变量来检验这个预测，结果是没有偏向，并给出了足够窄的置信区间。
- 定位：一个明确的、可证伪的预测得到了否定答案，可以作为论文的一部分，但不宜作为主线。

### 贡献 2（主线候选）：现有 agent memory benchmark 把"猜对"算成了"记住"

**论点**
- 常规记忆基准里的事实和偏好，大多是"合理的"或"可以猜到的"。即使记忆系统把它们丢了，底座模型也能凭先验答对。
- 因此，这些基准测的是"记忆 + 先验"的混合能力，系统的真实记忆能力被高估，系统之间的差距也被压平。

**我们现有的直接证据**
- Aider 实际保留率为 0%，常识题得分却是 97%；Codex 保留 7%，常识题 96%；Anthropic API 保留 9%，常识题 98%。
- 只看常识题，11 个系统全部挤在 95–99%，**几乎无法区分**。只看反常识题，分数从 1% 到 95% 依次拉开，排名与真实保留率基本一致。
- 混合题（一半常识、一半反常识）的分数也会把真实保留率高估 0.07–0.49。

**我们的 benchmark 设计**
- **成对的 minimal pair**：同一个槽位分别给出符合常识（C）和违背常识（I）的版本，其余内容完全一样。
- **核心指标**：
  - **反常识准确率**（I-accuracy）：唯一不能靠先验猜中的部分；
  - **信念差距**（C 准确率减 I 准确率）；
  - **扣除猜测之后的准确率**：(acc − g) / (1 − g)，其中 g 是不给记忆时的猜中率。
- **双重测量**：既看记忆文本的状态（保留、删除、翻转），也看 agent 的回答，从而区分"没存下来"和"存了但没用上"。
- **质量门槛**（V1–V3），每个条目都要逐条通过：
  - V1 先验强度：不给信息时，模型选常识版本的概率 ≥ 0.8；
  - V2 理解检验：刚听完就问，必须答对，排除"模型会主动纠正"的条目，例如 S02、S08；
  - V3 正对照：确认这套材料在从大意重建时能诱发单向规整。
- **条目的植入方式**：在完成别的任务时顺带提到，而不是郑重列成清单；不加 "actually" 之类的提示词；带有"规范性"标签。

**需要查新（必须先做）**
- **已知的相关做法**：
  - Zhang et al.（2605.12978）在 PropWorld 设计笔记里发现，用有意义的数值时，无记忆 agent 零样本可以答对 91%，于是改用无意义的 nonce；
  - MemoryAgentBench 的 FactConsolidation 用反事实更新值（MQuAKE），以避免参数知识泄漏；
  - knowledge-conflict 领域也有类似做法（ClashEval、ConflictQA、CounterFact）。
- **我们的区别**：
  - 他们是**消除**先验（nonce、反事实），我们是**量化**先验如何抬高分数，并且在保持内容真实、有意义的前提下把"记住"和"猜中"分开；
  - 用 nonce 测出来的记忆能力在现实中偏乐观或偏悲观都有可能，而反常识的真实知识（例如用户的特殊偏好、和常识相反的本地事实）恰恰是部署中最需要记住的内容。
- **待查**：是否已有工作系统地审计过主流 memory benchmark 的"无记忆可答率"（prior-answerable rate）。

**要把这一点立住，还需要的实验**
1. **审计现有基准**：在 LongMemEval、LoCoMo、MemoryAgentBench、PrefEval 等基准上跑"不给记忆"的条件，测出可被先验答对的题目比例。注意 LoCoMo 和 PrefEval 是 CC BY-NC，只做测量，不再分发。
2. **重新打分**：用现有基准评测几个主流记忆系统，比较原始分数、扣除猜测后的分数，以及只看不可猜题目的分数，看系统排名是否发生变化。
3. **扩展我们的 benchmark**：从 44 对扩到数百对；覆盖事实、流程、偏好、知识更新等类型；建立自动生成加 V1–V3 质量门槛的流水线；换多个底座模型重测先验，因为先验因模型而异。
4. **人工校验**：抽取 150 条，人工核对评判模型的标注，已有的样本可以复用。

### 贡献 3：决定损失的是改写的"范围"，而不是"有没有改写"
- 只改写局部相关条目的 Mem0 1.0.11 最稳：保留率 0.93，信念差距 +0.04。
- 只追加的 Mem0 2.2.1 只在写入那一刻（抽取阶段）丢东西，之后完全平稳。
- 每次把整份记忆重写一遍的系统，几个会话就丢掉大部分内容：LangChain、Codex、OpenHands、Anthropic API、Aider，以及 LlamaIndex 的 condense 步骤。
- 这对记忆系统设计有直接意义：局部更新或只追加，加上原始记录作为锚点，优于整体重写。
- 还需要补的实验：
  - 改变压缩触发频率和上限，比如 LlamaIndex 的 max_facts 用默认的 50；
  - 让无关会话带一些语义相近的干扰，测试局部更新何时会误伤；
  - 把缓解方式（锚点、局部更新）做成受控对照。

## 5. 论文框架草案（待定）
- **暂定题目**：*Your Memory Benchmark Is Measuring the Prior* 或 *Remembering vs. Guessing: Counter-Schema Probes Reveal What Agent Memory Actually Keeps*
- **结构**：
  1. 现象：记忆向先验退化，但发生在信念层面；
  2. 诊断：现有 benchmark 无法看到这一点（贡献 2）；
  3. 方法：minimal pair benchmark 加 V1–V3 质量门槛；
  4. 实证：11 个系统，揭示改写范围决定损失（贡献 3）；
  5. 理论：iterated learning 的预测被否定，"不加区分地删除、由先验补全"的机制得到支持（贡献 1）。
- **与 ACL 2027 主题的关系**：知识坍缩与同质化。记忆的损失让 agent 回到"平均"的先验，个体差异（用户的特殊偏好、本地的特殊事实）首先消失。

## 7. 查新结果（2026-10-06，3 个并行检索方向，所列论文均已打开原文核实）

**结论**："先验会抬高记忆评测分数"这个**原则本身不新**，不能作为贡献宣称。以下三点目前**没有人做过**，可以作为贡献：
- (a) 对**已有的主流 memory benchmark** 做系统的、逐题的、跨基准的"可被先验答对比例"审计，使用多个模型，并区分"强制猜测"和"允许不答"两种协议；
- (b) 用"抗先验子集"或"扣除猜测"的指标**重新给现有记忆系统打分**，看分数虚高和排名变化；
- (c) 在**同一个槽位**上做"符合常识与违背常识"的 minimal pair，覆盖事实、流程和偏好等多种类型，配上"记忆贡献"指标；并给出因果链："写入时删除不区分先验"导致"读取时向先验回归"。

**最接近的工作与撞车风险**

| 工作 | 内容 | 与我们的关系 |
|---|---|---|
| **PersonaMem-v2**（2512.06688） | 偏好分为刻板、中性、反刻板三类，准确率依次为 48.9%、41.6%、33.0%，并明确归因于 "population priors" | **最大撞车风险**，针对 (c)。区别：只涉及偏好；不是同一槽位的成对设计；没有无记忆基线和扣除猜测的指标 |
| Know It, Act on It（2607.29433） | 复现上面的刻板与反刻板差距；无记忆基线低于 3% | 同上 |
| Ground Truth First（2607.21962，独立作者） | 明确提出 "a memory score partly measures the model's priors"；在自己的虚构数据上，无记忆对照得 15–17% | 原则相同；没有审计 LoCoMo、LongMemEval，也没有重新打分 |
| MemGym（2605.20833） | 不做虚构化时，前沿模型凭预训练知识就能得 0.70–0.85；虚构化后接近 0 | 只针对它自己的基准 |
| LongMemEval-V2（2605.12493）、RECON（2607.16716）、EverMemBench、DolphinBench | 构建基准时就把能被先验答对的题过滤掉 | 只是"过滤"，没有回头审计旧基准 |
| 100-LongBench（2505.19293） | 长上下文 QA：无上下文基线显示分数虚高，修正后排名会变 | (a)(b) 在**长上下文**领域已有，在记忆领域还没有 |
| LastingBench、SeedRG、CConS、NoCha、ClashEval、FaithEval | 用反事实或违背常识的上下文、minimal pair 做忠实度评测 | 设计相同但领域不同，需要引用 |
| MirageBench（2608.04570） | 记忆中的刻板化"补全"（虚构用户属性），刻板 persona 高出 7.8 个百分点 | 对应我们"读取时由先验补全"的一个特例 |
| **Nemori**（2508.03341） | "Predict-Calibrate"：只存储模型预测不到的内容，是一种**考虑先验的写入策略** | **必须引用并作为对照**，否则"记忆删除不区分先验"这个说法要收窄 |
| Emergence AI 博客 | LongMemEval 上 "Best Guess" 基线得 18.8%，"I don't know" 基线得 5.8% | 非正式，只覆盖一个基准；和我们的结果一致 |
| MemDelta（2606.29914） | LongMemEval-S 上无记忆基线 2.2%，允许不答 | 说明协议不同，结论会差很多 |

**定位建议**：在记忆领域，现在的做法是在**新建**基准时把能被先验答对的题过滤掉，而在 RAG 和知识冲突领域，反事实上下文早已是标准设计。我们要做的是这些工作都没做的三件事：回头**量化**旧基准、**重新打分**、用**成对设计**估计每个条目对先验的依赖程度，并把写入和读取两端的因果机制连起来。

## 8. 现有基准的闭卷审计（第一轮：答题模型为 Qwen3-235B，评判模型为 gpt-oss-120b）

两种协议：
- **natural**：系统说明自己"记忆为空"，允许回答不知道。测的是一个什么都没存的系统，按标准协议能拿多少分。
- **forced**：必须给出最佳猜测。测的是能被先验答对的比例。

**解读（如实）**
1. **虚高程度因基准而异，从 7% 到 47%。** 不能笼统说"现有基准都被先验严重抬高"。
2. **MemoryAgentBench 的 Accurate Retrieval 受影响最大**：35–47% 的题闭卷就能答对，它自己的论文没有对这一部分做闭卷检查。
3. **LoCoMo**：
   - 如果把第 5 类算进去，一个什么都不存的系统也能**白拿 22.8 分**。
   - 第 1–4 类在强制猜测时有 16% 可被先验答对，其中 open-domain 达 32%。
4. **LongMemEval 相对稳健**：强制猜测 16%，和 Emergence 报告的 18.8% 一致；其中 temporal-reasoning 有 26%，因为很多题是二选一。
5. **PrefEval 本来就有意把题目设计成"违背默认行为"，所以虚高最小（7%）。** 这个结果印证了我们的思路：只有反先验的题目，才能测出真实的记忆能力。
6. **我们自己的 C/I 结果仍然是最强的证据**：在符合常识的题目上，各系统几乎无法区分（95–99%），而真实保留率是 0–93%。现有基准里的个人事实多是任意的（既不符合也不违背常识），所以虚高比我们的 C 条目小。

**下一步**
- 换第二、第三个答题模型重做审计（Llama-3.3-70B、gpt-oss-120b），检查结论对模型的依赖程度。
- 在虚高最严重的基准上（MemoryAgentBench-AR、LoCoMo）跑几个真实记忆系统，比较原始分数、扣除猜测后的分数和抗先验子集的分数，看排名是否变化。这是 (b)。
- 把 Nemori 作为考虑先验的写入策略，纳入框架实验。

## 9. Nemori（考虑先验的写入策略，作为对照）（2026-10-06）
- **版本与配置**：nemori @d2a6dff（MIT），使用默认配置，包括 episodic 分段、语义记忆和 Predict-Calibrate（`enable_prediction_correction=True`）；数据库用 PostgreSQL 和 Qdrant（docker）；压缩模型为 Qwen3-235B。
- **结果（第 12 个会话）**：C 和 I 的保留率都是 **1.00**，信念也都是 **1.00**；三项对比全部为 0。
- **解读**：
  - 在我们的设置下，Nemori 实际上是"全部存下"：只追加，没有容量上限，检索也很准。
  - Predict-Calibrate **没有把可预测的常识条目过滤掉**：C 和 I 两个版本都被写成了语义事实，例如"附件超过 25 MB 会被拒"。
  - 因此它没有表现出"按先验选择性写入"的行为。这进一步支持"改写范围决定损失"：Nemori、Mem0 1.0.11 这类局部更新、只追加加检索的设计最稳。
  - 代价是记忆体积会不断增长，第 12 个会话时有几十条语义事实，而且有大量重复。这个代价需要在论文里讨论。

## 10. 弱压缩模型（本地 Qwen3-8B，照搬原版 prompt 的 7 个系统；答题和评判模型不变）

第 12 个会话时的结果：

| 系统 | 保留 C / I（强模型 → 8B） | 信念差距（强模型 → 8B） | 保留率差 C−I（8B） | 翻转不对称（8B） |
|---|---|---|---|---|
| 中性重写 | 0.73 / 0.73 → **0.37 / 0.28** | +0.24 → +0.66 | **+0.091 [+0.007, +0.184]** | +0.012 [0, +0.028] |
| Gemini CLI | 0.45 / 0.54 → 0.04 / 0.04 | +0.38 → +0.88 | 0.000 | 0 |
| Codex | 0.06 / 0.07 → 0.02 / 0.01 | +0.84 → +0.95 | +0.006 | 0 |
| LangChain | 0.13 / 0.15 → 0.01 / 0.00 | +0.78 → +0.94 | +0.006 | 0 |

| Anthropic API | 0.08 / 0.11 → 0.04 / 0.04 | +0.84 → +0.93 | 0 | +0.006 |
| Aider | 0.00 / 0.00 → 0.00 / 0.00 | +0.96 → +0.92 | 0 | 0 |

**解读**
1. 弱模型**删得多得多**，大多数系统在第 12 个会话时基本删光，信念差距升到 +0.88 至 +0.95。
2. 弱模型**仍然几乎不改写**，翻转 ≤1.2%。所以"记忆文本被改写成常识版本"在强、弱两种模型上都不是主要机制。
3. **按先验方向删除开始出现**：在唯一没有删光的中性重写里，违背常识的条目多丢 9.1 个百分点（CI 不含 0）。其他系统已经触底，无法比较。
4. 违背常识的知识丢失 100% 来自删除。

**结论**：iterated learning 预测的"选择通道"在弱压缩模型上能看到苗头，在强模型上看不到；改写通道在两种模型上都几乎不存在。这一点可以写成一个有条件的结论：**压缩模型越弱，删除就越带有先验的方向性**。要把它坐实，还需要在不会触底的条件下补实验，例如加大容量上限或缩短链长。
