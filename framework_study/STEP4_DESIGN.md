# 第 4 步：换一个模型家族复现框架实验，设计与预先登记（v1.0）

写于 2026-10-11，对应 PLAN.md 第 4 步。**v1.0 在冒烟测试和成本核算之后、任何正式运行之前提交，提交时间就是登记时间。**分析代码 `src/analyse_step4.py` 与本文件同时提交。

## 1. 要回答的问题
原有框架实验（12 个系统，44 对条目，压缩模型是 Qwen3-235B）得出三条结论：
1. 记忆删除并不区分 C 和 I：保持率差 ΔR ≈ 0；
2. 改写几乎不会把内容翻成符合常识的版本：翻转不对称 ΔF ≤ 1%；
3. 被删掉的条目由先验补回来，所以信念差距 ΔK 很大。

另外，弱压缩模型（Qwen3-8B）在 neutral_roll 上表现出 +9.1 个百分点的先验导向删除。

本步要检验：(a) 这些结论在扩展后的 504 对数据集上是否成立；(b) 换一个模型家族之后是否成立。

## 2. 设计
- **模型家族**
  - Qwen3-235B（原设定）；
  - Llama-3.3-70B，作为第二个家族，同时担任压缩模型和读题模型。
  - 不选 gpt-oss-120b 的理由：它是记忆状态的两个评判模型之一，作压缩模型会形成自我评判；Llama 不承担评判，在 504 对里有 422 对先验够强（P(C) ≥ 0.8）。
  - 两个家族使用**同一组条目**和**同一组用户历史**，因此结果可以逐条对比。
- **条目子集 S4**
  - rule、procedure、preference、update 类：Qwen 和 Llama 上的 P(C) 都 ≥ 0.8；
  - neutral 类：两个模型上的 P(A) 都在 0.3–0.7 之间；
  - 而且都通过 V2（第 3 步已经要求 Llama 至少 3/4 答对）。
- **系统**（覆盖各类机制，共 9 个）

  | 机制 | 系统 |
  |---|---|
  | 上限 | raw_history |
  | 只追加 | mem0（2.2.1） |
  | 局部更新或删除 | mem0_v1（1.0.11） |
  | 事实块 | llamaindex_facts（max_facts 12，与原实验相同） |
  | 整份重写，产品原版 prompt | codex、aider、anthropic_api |
  | 整份重写，我们自己的 operator | neutral_roll |
  | 考虑先验的写入 | nemori |

- **用户历史**
  - 每个用户 8 个条目，C/I 版本在用户之间平衡分配；4 个种子会话，每个会话 2 个条目，之后接 12 个干扰会话。
  - 干扰会话取自第 3 步的池子，共 93 份，每个用户随机打乱。
  - **知识更新类**：旧值放在第 1 个种子会话里，作为一次额外的对话往来；更新放在该条目所在的种子会话里。规定 update 类不能分到第 1 个种子会话。
  - 用户数 N 在冒烟测试后按成本确定，目标是每个条目的 C、I 两个版本各至少出现一次。
- **检查点**：读完最后一个种子会话之后的第 0、4、12 个干扰会话。原实验用的是 0、2、4、8、12；本步为控制成本只用其中三个，最后一个检查点相同。
- **探针**：与原实验相同。
  - 记忆状态：gpt-oss-120b 和 gemma-3-27b 两个评判模型，只计两者一致的结果；
  - 信念：由**该家族自己的读题模型**根据该框架给出的上下文做强制二选一（T=0）。
- **压缩触发方式**：沿用原实验，每个会话结束后都压缩。会话本身很短，这样的频率接近长期使用；FINDINGS §11.4 讨论的压缩频率问题只适用于读长文档的场景。

## 3. 预测（在定稿时固定）
- **P4.1**（复现 ΔR ≈ 0）：Qwen 下，整份重写类系统（codex、aider、anthropic_api、neutral_roll）在最后一个检查点的 ΔR，95% 置信区间落在 ±0.05 之内。
- **P4.2**（复现 ΔF 很小）：Qwen 下，所有系统的 ΔF ≤ 0.02。
- **P4.3**（复现 ΔK 很大）：两个家族下，删除率 ≥ 50% 的系统都有 ΔK > 0，且置信区间不含 0；按系统统计，Spearman(删除率, ΔK) > 0。
- **P4.4**（跨家族）：
  - 各系统保持率的排名在两个家族之间相近：Spearman ≥ 0.7；
  - Llama 下的 ΔR 和 ΔF 如实报告；
  - 探索性预测：Llama 作为较弱的压缩模型，ΔR 比 Qwen 更偏正，参照 Qwen3-8B 的结果。
- **P4.5**（无先验对照）：两个家族下，neutral 类的 |ΔK| ≤ 0.10。
- **P4.6**（知识更新）：I 版本回到旧值的比例高于 C 版本，即更新方向违背先验时更容易丢失。指标是 P(信念 = 旧值 | I) − P(信念 = 旧值 | C) > 0，置信区间不含 0。
- **P4.7**（PCS 与真实保持率对照）：两个家族下，MAE(PCS, R) < MAE(原始准确率, R)，复现 METHOD P4。

所有置信区间都按用户聚类做自助法（B = 2000）。P4.1、P4.3、P4.4 是主检验，用 Holm 方法校正；其余是次要检验。

## 4. 冒烟测试与最终参数（2026-10-11）
- **冒烟测试**：2 个用户 × 9 个系统 × 2 个家族，3 个检查点。
  - 18 个运行全部成功；各系统在两个家族下都正常产生了记忆；Mem0 和 Nemori 在 Llama 下的 JSON 输出没有问题。
  - 读入加探针共花 $1.35，折合每个用户约 $0.68。
  - **披露**：我们看过这 2 个用户各记忆状态的计数，以确认流程正常，但没有计算任何预先登记的统计量。这 2 个用户就是正式运行里的第 0、1 号用户，请求会命中缓存，结果完全相同。
- **用户数 N = 192**：每个 S4 条目出现 3–4 次，C/I 版本平衡分配。
  - 选这个数是为了让最后一个检查点上每个系统的 ΔR 置信区间约为 ±0.045，这样 P4.1 的 ±0.05 标准才检验得出来；108 个用户时约为 ±0.06。
  - 估计花费约 $130，在第 4 步 $150 的预算之内。
- 条目子集 S4 共 432 对：规则 250、知识更新 67、流程 63、偏好 42、无先验对照 10。
